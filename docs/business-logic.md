# Бизнес-логика расчёта стоимости рейсов

## Назначение

Компания перевозит сборные грузы: в одном рейсе участвуют грузы нескольких
клиентов. Стоимость каждого рейса распределяется между этими клиентами, а
затем входит в их месячные счета.

## Распределение стоимости рейса

Стоимость рейса распределяется пропорционально суммарному объёму грузов
клиента в рейсе, в м³.

1. Для каждого клиента суммируется `cargo.volume_m3` по рейсу.
2. Суммируются положительные объёмы всех клиентов.
3. Доля клиента равна его положительному объёму, делённому на общий объём.
4. Стоимость переводится в целое число копеек и распределяется по этим долям.

Вес и число палет на распределение стоимости не влияют. Они используются для
логистических данных и отчёта о загрузке машины.

### Данные без объёма

- `NULL` и `0 м³` означают нулевой объём: такой груз получает `0 ₽`.
- Отрицательный объём недопустим: расчёт и формирование счетов прекращаются с
  ошибкой данных.
- Если во всём рейсе нет положительного объёма, распределить стоимость по
  объёму невозможно. Формирование счетов прекращается; созданные в рамках
  этого запуска счета и строки откатываются.

## Правило округления

Распределение выполняется в копейках, поэтому сумма начислений по рейсу всегда
в точности равна его стоимости.

Сначала каждая доля округляется вниз до целой копейки. Нераспределённые копейки
получают клиенты с наибольшей дробной частью. Если дробные части одинаковы,
приоритет получает меньший идентификатор клиента. Это правило делает повторный
расчёт на одинаковых данных воспроизводимым.

Например, рейс стоимостью `100,00 ₽` и тремя клиентами с одинаковым объёмом
будет распределён как `33,34 ₽`, `33,33 ₽`, `33,33 ₽`. Дополнительную копейку
получит клиент с меньшим ID.

## Счета за месяц

При формировании счета учитываются рейсы, в которых у клиента был груз, с
датой отправления выбранного месяца и статусом, отличным от `cancelled`.

Повторный запуск пересчитывает строки существующего счёта и его сумму. Статус
счёта, дата отправки и дата выгрузки в 1С сохраняются. Если обнаружена ошибка
объёма, транзакция откатывается: частично пересчитанных счетов не остаётся.

## Ручная проверка

### Подготовка

1. В корне проекта выполните `php bin/reset-db.php`.
2. Запустите приложение: `php -S localhost:8000 -t public`.
3. Откройте `http://localhost:8000/trip.php?id=6`.

В демонстрационных данных рейс `КЗН-1106` стоит `50 000,00 ₽`; у трёх клиентов
по `4,0 м³`. На странице должны быть суммы `16 666,67 ₽`, `16 666,66 ₽` и
`16 666,66 ₽`. Их итог — ровно `50 000,00 ₽`; лишняя копейка назначена клиенту
с наименьшим ID.

### Проверка формирования счетов

1. Откройте страницу `http://localhost:8000/invoices.php`.
2. Выберите месяц `2026-09` и нажмите «Сформировать».
3. Откройте любой счёт и сравните суммы его строк с карточками соответствующих
   рейсов.
4. Сформируйте счета за тот же месяц ещё раз. Суммы и число строк не должны
   измениться или задвоиться.

### Проверка ошибки данных

В демонстрационных данных у рейса `НН-1108` (`trip.php?id=8`) нет грузов с
положительным объёмом. Карточка рейса должна показать сообщение, что
распределение невозможно. При формировании счетов за `2026-10` приложение
должно вернуться к списку счетов с тем же сообщением, без частично созданных
счетов.

## API долей рейса

`GET /api/trip_split.php?trip_id={id}` возвращает JSON с номером и стоимостью
рейса, а также долями клиентов. Для каждого клиента передаются число грузов,
общий вес, общий объём, доля и начисленная сумма. Денежные значения `cost` и
`amount` передаются строками с двумя знаками после точки.

Например, для рейса 11:

```bash
curl 'http://localhost:8000/api/trip_split.php?trip_id=11'
```

```json
{
  "trip_id": 11,
  "number": "МСК-1111",
  "cost": "48750.50",
  "clients": [
    {"client_id": 1, "cargo_count": 2, "weight_kg": 120, "volume_m3": 8, "share": 0.8, "amount": "39000.40"},
    {"client_id": 2, "cargo_count": 1, "weight_kg": 2000, "volume_m3": 2, "share": 0.2, "amount": "9750.10"}
  ]
}
```

- Если рейс не найден, API возвращает `404` и JSON с полем `error`.
- Если доли нельзя рассчитать из-за объёма, API возвращает `422` и описание
  ошибки в поле `error`.

## API счетов за месяц

Формирование счетов состоит из двух шагов.

### Предпросмотр

`GET /api/billing_preview.php?period=YYYY-MM` строит расчётный план и **не
изменяет базу данных**. В ответе передаются текущая и расчётная сумма каждого
затронутого счёта, разница, а также общие суммы до и после расчёта. Для ещё не
созданного счёта `invoice_id` имеет значение `null`, а `before` равно `0.00`.

### Применение

`POST /api/billing_apply.php` с form-параметром `period=YYYY-MM` применяет тот
же расчёт: создаёт недостающие счета, обновляет отличающиеся и оставляет без
записи совпадающие. В ответе есть счётчики `created`, `updated`, `unchanged` и
список действий по клиентам.

Повторное применение на тех же данных возвращает `unchanged` и не создаёт
дубликатов строк. Если расчёт невозможен из-за объёма груза, оба API возвращают
`422`; при применении транзакция откатывается целиком.

### Ручная проверка API счетов

1. Пересоздайте демонстрационную базу: `php bin/reset-db.php`.
2. Запустите приложение: `php -S localhost:8000 -t public`.
3. Выполните предпросмотр за сентябрь и убедитесь, что список счетов в браузере
   не изменился:

   ```bash
   curl 'http://localhost:8000/api/billing_preview.php?period=2026-09'
   ```

4. Примените расчёт:

   ```bash
   curl -X POST -d 'period=2026-09' http://localhost:8000/api/billing_apply.php
   ```

   Ответ должен содержать ненулевые `updated` для исходных счетов.
5. Повторите POST тем же запросом:

   ```bash
   curl -X POST -d 'period=2026-09' http://localhost:8000/api/billing_apply.php
   ```

   В ответе должны быть `created: 0`, `updated: 0` и `unchanged: 6`; счета и
   строки не должны измениться или продублироваться.

## Карточка рейса: распределение стоимости

В карточке рейса блок «Распределение стоимости» получает данные только через
`GET /api/trip_split.php`. JavaScript на jQuery выводит по каждому клиенту:
число грузов, общий вес, общий объём, процентную долю и начисленную сумму.

Внизу блока показаны два независимых итога: сумма начислений по клиентам и
стоимость рейса. Они должны совпадать до копейки. Если API сообщает об ошибке
данных объёма, вместо строк распределения выводится сообщение; значения итогов
не показываются как корректные.

### Ручная проверка блока

1. Запустите приложение и откройте `http://localhost:8000/trip.php?id=11`.
2. В блоке «Распределение стоимости» должны появиться две строки: ООО
   «Хрустим» (2 груза, 120 кг, 8 м³, 80 %, `39 000,40 ₽`) и ООО «Родник»
   (1 груз, 2 000 кг, 2 м³, 20 %, `9 750,10 ₽`).
3. Убедитесь, что «Итого по клиентам» и «Стоимость рейса» равны
   `48 750,50 ₽`.
4. Откройте `http://localhost:8000/trip.php?id=8`. Вместо распределения
   должно отображаться сообщение о невозможности расчёта, поскольку нет
   положительного объёма.

### Браузерная проверка

Для проверки работы jQuery-интерфейса используется Playwright. Установите
Node.js-зависимости и Chromium один раз:

```bash
npm install
npx playwright install chromium
```

Запуск:

```bash
npm run test:browser
```

Тест поднимает приложение на отдельной временной базе `data/browser-test.sqlite`
и не изменяет рабочую `data/app.sqlite`. Он проверяет отображение данных API и
итогов для рейса 11, сообщение об ошибке для рейса 8, а также HTTP-сценарий
предпросмотра и повторного применения месячных счетов.
