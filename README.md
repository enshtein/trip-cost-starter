# Рейсы и счета

Небольшая система учёта рейсов сборных грузов и счетов клиентам.

## Запуск

Нужен PHP 8.2+ с расширением `pdo_sqlite`.

```bash
php bin/reset-db.php
php -S localhost:8000 -t public
```

Открыть http://localhost:8000.

Через Docker (используется PHP 8.2):

```bash
docker build -t trip-cost-starter .
docker run --rm -p 8000:8000 trip-cost-starter
```

При каждом запуске контейнера база пересоздаётся из схемы и тестовых данных.

## Тесты

Установить зависимости и запустить тесты бизнес-логики:

```bash
composer install
composer test
```

Тесты используют отдельную временную SQLite-базу и не изменяют
`data/app.sqlite`. Они проверяют распределение стоимости по объёму,
детерминированное распределение остаточных копеек, формирование и
пересчёт счетов, а также отбор и отметку счетов при выгрузке в 1С.

Чтобы увидеть названия выполненных сценариев, запустите:

```bash
composer test -- --testdox
```

### Браузерные тесты интерфейса

Браузерные тесты на Playwright проверяют работу интерфейса в Chromium: загрузку
данных через JavaScript, отображение данных API и обработку ошибок.

Первичная установка:

```bash
npm install
npx playwright install chromium
```

Запуск:

```bash
npm run test:browser
```

Тесты запускают приложение на отдельном порту и используют временную базу
`data/browser-test.sqlite`, поэтому не затрагивают рабочую `data/app.sqlite`.

### Как попросить помощника проверить интерфейс

Примеры запросов для работы с помощником:

- «Создай браузерные тесты для нового интерфейса и проверь их в Chromium».
- «Запусти браузерные тесты и покажи, какие пользовательские сценарии они покрывают».
- «Проверь вручную и браузерным тестом страницу карточки рейса после изменения JavaScript».
- «Добавь в браузерные тесты сценарий ошибки API и опиши ручную проверку в документации».

После завершения помощник должен показать изменённые файлы, результаты
автоматических проверок и `git diff`; коммит создаётся только по отдельной
команде.

Подробные правила расчёта и порядок ручной проверки: [docs/business-logic.md](docs/business-logic.md).

`php bin/reset-db.php` пересоздаёт базу `data/app.sqlite` из `data/schema.sql` и `data/seed.sql`. Так можно вернуть
исходные данные в любой момент.

## Что сделано и ограничения

Реализованы распределение стоимости рейса по объёму, API и блок распределения
в карточке рейса, безопасный предпросмотр и применение пересчёта счетов, а
также экран «Счета за месяц». Пересчёт повторяем: повторное применение периода
не создаёт дублирующих строк и счетов.

Рейс можно рассчитать по новому правилу, только если хотя бы у одного его
груза указан положительный объём. Рейсы без таких данных не пересчитываются —
экран показывает их отдельным предупреждением. Для существующего счёта прежняя
строка такого рейса сохраняется; новый счёт только для такого рейса не
создаётся. Расчёт по весу как запасной вариант намеренно не применяется, потому
что он противоречит новому правилу. Чтобы пересчитать исключённый рейс, нужно
внести объём хотя бы для одного его груза.

## Что внутри

| Папка | Что в ней |
|---|---|
| `public/` | Страницы, API (`public/api/`), скрипты и стили |
| `lib/` | Подключение к базе, общие функции, расчёт счетов |
| `data/` | Схема и данные |
| `bin/` | Служебные скрипты |

## Страницы

| Страница | Адрес | Для чего |
|---|---|---|
| Рейсы | `index.php` | Журнал рейсов: куда, когда, на какой машине, сколько стоит |
| Карточка рейса | `trip.php?id=` | Грузы клиентов в рейсе и доля каждого клиента в стоимости |
| Счета клиентов | `invoices.php` | Счета за месяц: сумма, статус, когда отправлен клиенту и выгружен в 1С. Здесь же счета формируют |
| Счёт | `invoice.php?id=` | Из каких рейсов сложилась сумма счёта |
| Загрузка машин | `load_report.php` | Отчёт для логистов: насколько загружена машина по весу и какую долю стоимости рейса получает клиент |
| Выгрузка счетов в 1С | `export_1c.php` | Файл для бухгалтерии: отправленные счета, которые ещё не выгружены |

## API

`GET /api/trip_split.php?trip_id=11` возвращает стоимость рейса и доли клиентов
по объёму груза в формате JSON. Если рейс не найден, метод возвращает `404`.

`GET /api/billing_preview.php?period=2026-10` показывает изменения счетов за
месяц без записи в БД. `POST /api/billing_apply.php` с параметром
`period=2026-10` создаёт или обновляет счета и сообщает количество созданных,
обновлённых и неизменённых счетов.

Страница `billing.php` даёт тот же двухшаговый сценарий в интерфейсе: сначала
предпросмотр, затем подтверждённое применение.
